## Requirements

**1. One deny-by-default writer: PASS.**
- Glue: exactly one MMIO store, `sb.i2c[off / 4u] = v` in `sb_wr32` (P:99), HSI2C12 block only, aligned and bounded by the ADT `reg` length 0xC8 (P:96). Pad bank, sysreg and CMU are mapped but only read (`sb_rd32`, P:64-89). Other stores in the glue are to its own static struct.
- Header: `ops->wr32` is called once (P:719), inside `sfg_w32` (P:705-720), after `sfg_reg_writable` (P:711, seven offsets, P:662-667) and `sfg_w32_allowed` (P:717, P:683-702); anything else returns -2 without a read.
- The 16 `sfg_w32` call sites: `sfg_msg_start` P:777 FIFO_CTL, P:779 INT_STATUS w1c, P:783 ADDR, P:785 CTL, P:787 INT_ENABLE, P:789 AUTO_CONF, P:793 AUTO_CONF|RUN; `sfg_xfer` P:811 TX_DATA, P:815 INT_STATUS, P:829 INT_STATUS; `sfg_restore` P:913 AUTO_CONF, P:914 ADDR, P:915 CTL, P:916 FIFO_CTL, P:917 INT_ENABLE, P:919 INT_STATUS.
- Reads go through `sfg_rd_ok` (P:630-644, stricter than the shim); RX_DATA is read only in `sfg_rx_pop` after FIFO_STATUS said not empty (P:655-659, P:822-823). TX_DATA is never read.
- Caveat: F1.

**2. Delta against the shim: PASS, no additional controller write.** I compared the functions side by side and listed the call sites mechanically: same 16 sites, registers, values and order (S:291-307, :322, :326, :340, :399-405). `sfg_w32_allowed` equals `w32_allowed` (S:212-231) clause for clause; `sfg_poll`/`sfg_wait`/`sfg_idle_wait`/`sfg_restore` equal `poll_st`/`wait_for`/`bus_idle_wait`/`restore`; the gate equals `peri_gate` (pk-peri `shim/periprobe.h:52-71`); the 12 preconditions equal `precondition()` (S:346-373). Host test expects the literal shim values 0x00010013, 0xD800, 0x88, 0x80, 0x1, 0x80000001 / 0x00020023, 0x48, 0x00030002, 0x80030002 (host test :416-417). Differences, all of them:
1. Seven pointers instead of five: Current 0x0A and DevName 0x21 added (P:296). Both are plain regmap reads in the Google driver (bms `max_m5.c:1630`, `max1720x_battery.c:1144`, `:5945`) and lie in 0x00..0x4F (`max_m5.c:1595`). Per set 7 x 17 + 6 = 125 writes instead of 91.
2. Extra precondition: nine live words must equal the handoff words (P:864-881). Stricter. The words match run oriole-fg1 (*observed*, pk-peri `logs/probe/20261114T122646Z-oriole-fg1_`: CTL 48, FIFO_CTL 00080083, INT_EN 80, ADDR 9400, AUTO_CONF 00030001, CONF 980110FF, TIMEOUT FF, TRAILING 00FFFFFF, USI_CON 0).
3. Constants from the ADT instead of generated macros (F1).
4. Repeats every 30 s; first refusal, failure or failed restore latches `stopped` (P:1032, P:1126, P:1131) and the thread ends (P:184-187). The shim ran once.
5. Runs with interrupts on and other threads alive; each transfer and the restore under `disable_preemption` (F2). The shim was single-threaded.
6. MMIO faults: the shim's `try_read32`/`try_write32` survive an abort, the glue's direct access does not (a gated block would panic instead of refusing). The gate order (sysreg, CMU, pads, then controller) is the shim's.
7. Timebase: `mach_absolute_time` with ticks per second from `nanoseconds_to_absolutetime` (P:237) instead of CNTPCT/CNTFRQ; same 10 ms limit.
8. Output only: the restore lines are printed after the writes and only on the first set or a failure; no per-register failure words (F5); `sfg_restore` reads ERR/FIFO/TRANS before the "unreadable" return (three more reads, no write).
9. The restore still writes ADDR back to 0x9400 (0x25 << 10, the bootloader's last target) as the shim does; MASTER_RUN is refused unless ADDR reads 0xD800 (P:696) and is never a restore value (P:695), so no start can go to 0x25.

**3. Constants traceable: PASS.** All offsets, bits, fields come from `soc.json` hsi2c/peri, which are identical to the reviewed shim branch (*observed*: JSON compare of both blocks and their notes, equal). I re-checked the values mkadt emits against soc-gs `i2c-exynos5.c` @2040787 defines (CTL 0x00 .. ADDR 0x70, MASTER bit 3, RXCHON 6, TXCHON 7, triggers << 4 / << 16, TRANS_DONE bit 7, FIFO bits 7/8/23/24, CONF 29/30/31, AUTO 16/17/31, BUSY 16/17, MAS << 10, states 0/1/0xB/0xC, trailing 0xFFFFFF): equal. Gauge: `max_m5_reg.h:209,219,224,229,234,548,894`; 0x36 on hsi2c_12 `gs101-raviole-battery.dtsi:150-155,182-185`; rsense 500 `:193`. Not from a source, by design (policy, not hardware): `SFG_XFER_MS` 10, `SFG_POLLS` 100000, `SFG_TICK_SPINS` 1000, `SB_FIRST_S` 20, `SB_PERIOD_S` 30, the structural limits in `sfg_cfg_load` (0x1000, 0x100, 64 KiB, shift <= 24), `tx_fifo_depth` 16 (the driver's FIFO is 0x40; the lower value is the shim's, conservative), 0xf for `dsb sy`.

**4. Bounds: PASS.** `sfg_wait` P:753-767: <= 100000 polls and <= 10 ms from the start of the message. `sfg_idle_wait` P:893-899: same. `sfg_counter_runs` P:988: 1000. Byte loop P:821: 2. Register loops P:1055, P:1086, P:1101: 7. `sfg_cfg_load` P:451-471: 7, 15 x 15, 28. Text helpers P:513, P:522, P:536, P:542: <= 199, 8, 10, 10. Per set: about 2 ms when healthy; worst case about 20 ms in one transfer window plus about 10 ms in the restore, each with preemption off. No lock is taken anywhere (the header has none; the glue has none). The thread sleeps in `tsleep` between sets (P:183, P:185). Every return-1 path of `sfg_set` latches `stopped` (P:1050, P:1029-1034, P:1126), `sfg_set` then returns before any access (P:1050), and the thread leaves its loop on the first nonzero result. Test gap: F3a. Period guard: F6.

**5. Stop paths: PASS.** Refusals before the first write (timer, gate, pads, unreadable, preconditions, handoff) write nothing and need no restore. After the first write attempt the restore always runs (P:1094-1097): bounded idle wait first (shim F1), six writes, nine words read back, `restore=ok` only if all writes were accepted, the five words equal the snapshot, INT_STATUS 0, ERR 0, not busy, both FIFOs empty (P:929-932; shim F3); otherwise `!!! RESTORE FAILED`, the values, `restore=FAILED`, reader stopped. Left changed after a good restore: nothing in the controller; the gauge's register pointer (volatile, last 0x21). After a failed restore: what the `restore`/`after` lines show, possibly the bus held without STOP (F7). Host test covers NACK, timeout, arbitration, ERR_STATUS, faulting and dropped writes (*observed*: PASS).

**6. Default off: PASS.** `sweet_batt_init` returns at P:207-209 when the argument is absent or 0, before `SecureDTLookupEntry` (P:214), `ml_io_map` (P:229) and the thread (P:247); a value other than 1 is refused (P:210). The node alone is never looked at. The audit pins the order and my mutant removing `on == 0` was killed. `sweetbatt` is not in any `xnu_bootargs_default` (grep). With the argument but no node (bluejay, sweet): refused, nothing mapped. Caveats: F4.

**7. Limits: PASS.**
- Address: `v_addr = 0x36 << shift` (P:416), `fg-addr7` must be 0x36 (P:449), RUN needs ADDR == `v_addr` read just before (P:696, P:715). With the generated ADT `v_addr` = 0xD800 (*observed*, host test).
- Registers: TX_DATA accepts only the seven pointer bytes (P:700, P:326-332); `fg-regs` must equal the list (P:451-453); mkadt refuses any other list or address (`tools/mkadt.py` sweet_batt_props; `tools/test_mkadt_batt.py:101-118`).
- No data-byte write: the only write message is `v_auto_w` = length 1, no STOP (P:417); a RUN is accepted only for `v_auto_w` or `v_auto_r` (P:696). Even an arbitrary sequence of allowed writes can send at most one byte per write message, and that byte is a pointer.
- 0x69 / 0x25 / 0x57 / 0x66: never a transfer target (static assert P:301; no RUN unless ADDR == 0x36 << 10). ADDR holds 0x25 << 10 at rest because the bootloader left it so and the restore puts it back, without RUN (item 2.9).
- No reset, no reconfiguration: CTL values are MASTER|TXCHON, MASTER|RXCHON or the snapshot with only channel bits beside MASTER (P:687), so SW_RST (bit 31) is unreachable; CONF 0x40, TIMEOUT 0x48, TRAILING 0x08, timing 0x54-0x6C, CLK_CTL, MANUAL_CMD 0x4C, USI_CON 0xC4 are not writable (P:665-666 with the generated offsets). Sysreg, CMU and pads are never written.
- Touch output: `tools/test_mkadt_touch.py` is untouched and passes. I also serialised the ADT at 09235cb and at HEAD with a fixed seed: sweet and bluejay byte-identical (sha256 prefixes ee3942191cb5 / 284d20c69297 both sides); oriole differs only by the added `/sweet-batt` child, every other child node hash equal (sweet-touch b959f0d8338e both sides).

**8. Worst case on the phone.**
- Panic or hang: an MMIO read of a gated block (item 2.6), or F2. A hang with the bus held is also possible if an unrelated panic lands in the roughly 100 us between the two messages. Interrupt storm: INT_ENABLE is 0x80 at handoff and TRANS_DONE now becomes pending for microseconds per message; XNU never enables an SPI, and run gpu-oriole-g4b (*observed*, pk-dev `logs/runs/20261114T103400Z-gpu-oriole-g4b`, patch 0109 probe) printed no non-zero GICD ISENABLER word, so the USI12 interrupt cannot reach the CPU. That observation is the non-secure view of one boot.
- Bus wedge: after a failure between the pointer write and the read, the controller holds I2C12 (no STOP) and the reader stops. The TCPC (0x25), charger (0x69), PMIC interface (0x66) and PCA9468 (0x57) share the bus and become unreachable from the AP. No XNU patch talks to any of them (grep: 0148 is the only patch naming HSI2C12 / 0x10D50000), so nothing in XNU changes behaviour; the chips keep running on the settings the bootloader left, as they do in every XNU boot today. No device register is written (only the gauge's pointer), no charger or protection limit is touched, nothing non-volatile.
- Gauge stuck mid-byte needs the master to stop clocking inside a read byte; auto mode clocks whole bytes and the restore waits for idle first. *Guess* (carried from the shim review): the gauge frees its interface on a bus timeout or the next START.
- Power cycle: everything changed is volatile SoC register state plus the gauge's pointer. A reset reinitialises USI12 in the bootloader (*guess*, same as the shim review; supported by normal boots after the shim runs). Power + Volume Down reaches fastboot as always; no partition is involved.

## First-run notes (not conditions of the verdict)

Use `tools/xrun ... --args "sweetbatt=1"` on oriole only, not in a boot that also ran the shim `--fg-read`. Expect within about 25 s: `reader armed (HSI2C12 0x10d50000, device 0x36)`, four `before` lines equal to the handoff words, `restore wait idle=1`, `raw 06=.. .. 21=.... restore=ok`, then `soc=.. v=.. mV`. Compare v with `fastboot getvar battery-voltage` and the oriole-fg1 values. Any `refused`, `RESTORE FAILED` or `BUS NOT IDLE`: stop, save the log, power-cycle before anything else.
